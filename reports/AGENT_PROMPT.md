# CHQ Report Analysis — Agent Prompt (Public Template)

Use this prompt to analyze a `chq` HTML report with an AI agent.

---

## Prompt

```
You are analyzing a ClickHouse query performance report generated by the `chq` tool.
The report covers one week of query_log data from a ClickHouse cluster.

## Your task

Read the full HTML report at `report.html` (or as provided) and produce a complete, structured
analysis with prioritized, actionable recommendations.

## Cluster context (fill these in)

- Cluster: <cluster-hostname>
- Environment: <prod|staging|dev>
- Source table: <db.table> (e.g. monitoring.chq_query_log)
- Excluded users (noise): <list>

## Report sections to read (in order)

1. Executive Summary — health score, key findings
2. Cost Attribution → By User — who owns the cost
3. Top N → By Duration, By Memory, By Read Bytes, By Weighted Cost
4. Anti-Patterns → Full Scans, Missing Partition Filter, Repeated Identical, Select Star Wide Tables, Small Insert Batches, Unbounded Results
5. Cluster Health → Insert Duration By Engine, Insert Part Fragmentation, Merge Pressure, Partition Health
6. Anomalies → New Expensive Patterns, WoW Duration Regressions

Read ALL sections completely before writing any analysis. Do not skip rows.

## Output format

### Summary table
| # | User | Pattern | Impact | Frequency |
|---|------|---------|--------|-----------|
List the top 10 issues ordered by estimated impact (e.g. read bytes × frequency).

### Prioritized recommendations

#### P0 — Fix This Week
For each issue: user, query pattern, metric (executions/week, total read, scan ratio, etc.),
root cause, and a specific fix.

#### P1 — Fix Soon
Same format.

#### P2 — Good Practice
Same format.

### Cluster health notes
Summarize fragmentation, merge pressure, and partition health issues with table names and severity.

### Appendix
- Call out any recurring query patterns that show up across multiple sections.
- If relevant, suggest changes to batching/caching/partitioning and how to validate improvements.
```
